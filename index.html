Process

How a build goes through my hands

Every step leaves evidence behind (logs, screenshots, a Jira ticket) so anyone on the team can check the result.

  1. 01

    Review the spec

    Requirements, designs and event specs, reviewed with the team. Unclear points get asked about early, not guessed.

  2. 02

    Design test cases

    Risk-based: critical gameplay and monetization first, then edge cases like network loss and duplicate payments.

  3. 03

    Test on real devices

    Android, iOS and PC builds, with logcat or Unity Console open to catch what the screen doesn't show.

  4. 04

    Report the bug

    Clear steps, expected and actual results, environment, repro rate and attachments in Jira.

  5. 05

    Verify the fix

    Retest the fix, then run regression around it so nothing else breaks.

  6. 06

    Sign off

    Report to the team with what passed, what failed and what couldn't be tested yet.

How it was tested

  • Remote Config set per case by writing onboard_config into the debug build's config cache, then restored to the real values afterwards.
  • "No ad" simulated by pointing the native request at a banner test unit so it fails with a format mismatch. A 1 ms timeout was tried first and did not work.
  • Every test ad looks the same, so ad swaps and reuse were checked from onAdImpression logs: unit name and timestamp.
  • Compared with the previous build 1.0.2 on the same device to separate new bugs from old behavior.

Bug report

A bug I reported

A developer should be able to reproduce it from the ticket alone, without asking me anything.

This is a real bug I found and reported. The product name and internal details are left out; the steps, results and config are as filed.

FAILIAP · Coin·Android · v1.1.2·Reproduce 100%

[IAP – Coin] earned_coin is deleted on account deletion even when Restore config = false

With Restore = false, deleting an account should remove only the purchased_coin tied to that account. earned_coin is tied to the device, so it must be kept after the account is deleted.

Instead, both purchased_coin and earned_coin are deleted. After logging in again, the user receives the default coin_initial amount again, even though it was already granted before.

Environment

Platform
Android
Device
Android phone
Build
v1.1.2
Config
Restore = false

Steps to reproduce

  1. Set Restore config to false.
  2. Log in to an account that has earned_coin and/or purchased_coin.
  3. Delete the account.
  4. Check the coin balance after the account is deleted.
  5. Log in again.
  6. Check the coin balance again.

Actual result

  • purchased_coin is deleted.
  • earned_coin is also deleted, even though it is device-bound.
  • After logging in again, the user receives 1 coin from coin_initial.
  • The previous earned_coin balance is not kept.

Expected result

  • The account-bound purchased_coin is deleted.
  • The device-bound earned_coin is kept.
  • After logging in again, earned_coin is still intact.
